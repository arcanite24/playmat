# Mana@Home S5: GPU workers, batch inference sidecar, and large-network project

S5 of [the design](Design.md): CUDA/MPS GPU worker support (`UnitKind::SelfplayGpu`), zero-copy batched inference via
`infer_server.py --pmnet`, GPU host leasing and replay-based verification, CPU-vs-GPU parity verification, and the
large-network training workflow. S4's record is in [S4.md](S4.md).

## What S5 built

- **Batched `.pmnet` GPU inference sidecar** (`rust/rl/infer_server.py`):
  - Added `--pmnet <file>` so `infer_server.py` loads any SHA-256-verified `.pmnet` downloaded from the coordinator
    directly (zero-padding legacy v1/v2 `glob` input weights to `GLOB_F = 89` to match `playmat-ai/src/net.rs`).
  - Supports `--device auto|cuda|mps|cpu`, `bf16` autocast on CUDA (`--amp 1`), and optional `torch.compile`.
- **Coordinator GPU leasing and verification** (`playmat-swarm-proto/src/api.rs`, `playmat-swarm/src/{lib.rs, trust.rs, admin.rs, public.rs}`):
  - `Hello` and `HostInfo` carry optional `gpu: Option<String>` (e.g. `cuda:RTX 4080` or `mps:apple-silicon`), persisted
    via idempotent migration `ALTER TABLE hosts ADD COLUMN gpu TEXT` and counted in `GET /api/v1/status` (`gpu_hosts`).
  - `POST /api/v1/lease` leases `UnitKind::SelfplayGpu` units exclusively to hosts that reported a GPU, allowing
    `vloss > 1` and non-strict builds.
  - Because GPU floating-point rounding differs from CPU `strict`, `trust::should_rerun` routes completed
    `UnitKind::SelfplayGpu` units to deterministic `VerifyMode::Replay` (verifying every game's answer log, rule
    legality, outcome, and uploaded file hashes on any reputable/trusted verifier) paired with S2 per-worker statistical
    residual monitoring.
- **Worker GPU execution and parity check** (`playmat-worker/src/{gpu.rs, main.rs, swarm.rs}`):
  - `playmat-worker run --gpu auto` (or `MANA_GPU=auto`) auto-detects NVIDIA GPUs (`nvidia-smi`) or Apple Silicon MPS.
  - For `UnitKind::SelfplayGpu` leases, the worker still verifies each downloaded `.pmnet` against its pinned SHA-256,
    spawns a loopback `infer_server.py --pmnet <file> --port 0` sidecar, rewrites `@<sha256>` -> `tcp://127.0.0.1:<port>`
    at execution time so `playmat-ai`'s `RemoteNet` coalesces virtual-loss waves into GPU batches while work units stay
    pure data, and tears down the sidecar when the unit finishes.
  - Added `playmat-worker parity --pmnet FILE [--device auto|cuda|mps|cpu] [--cases 32] [--tol 0.01]` to verify
    batched GPU outputs against strict CPU evaluation.
- **CUDA container image and trainer CLI** (`ops/swarm/Dockerfile.worker-gpu`, `.github/workflows/mana-images.yml`,
  `rust/rl/swarm.py`):
  - Multi-stage CUDA 12.4 runtime image (`ghcr.io/arcanite24/mana-worker-gpu`) built on `amd64` with `playmat-worker`,
    PyTorch CUDA, `infer_server.py`, and pinned card suites.
  - `swarm.py publish-gpu` publishes `UnitKind::SelfplayGpu` rounds (`strict: false`, default `vloss=8`) for larger
    Transformer (`Tx`) projects.

## GPU parity measurements

Measured with `playmat-worker --features strict parity` against PyTorch 2.8.0 (`infer_server.py --pmnet`, Apple Silicon
MPS, 32 batched observations across 4 entity/action shapes, tolerance `0.01`):

| Network | Parameters | Max logit diff | Max value diff | Result |
| --- | ---: | ---: | ---: | --- |
| Built-in MLP (`playmat-ai/src/net.pmnet`) | 139K | `0.000011` | `0.000002` | Pass |
| Large v3 `Tx` (`d=256, heads=8, layers=6, ff=512, dim=64, trunk=256, glob_f=89, gelu=1, rel=1, act_ent=1, val_mlp=1`) | 4,341,300 | `0.000005` | `0.000001` | Pass |

## Rust native GPU backend (`--features gpu-wgpu`)

`playmat-ai` also includes an optional zero-Python native GPU compute backend (`rust/crates/playmat-ai/src/gpu_wgpu.rs`,
enabled via `--features gpu-wgpu` and `PLAYMAT_WGPU=1`) running batched dense projections (`Y = act(X @ W^T + b)` with
ReLU, tanh-approx GELU, and residual accumulation) directly on Metal (Apple Silicon), Vulkan, or DX12 via WGSL compute
shaders.

- **Why the PyTorch TCP sidecar still ships as default for CUDA Docker**: `infer_server.py` batches full multi-layer
  `Tx` waves in one round-trip with `bf16` tensor-core autocast and `torch.compile`, while `gpu-wgpu` stays strictly
  optional behind a Cargo feature flag so CPU `strict` and WASM builds stay fast with zero GPU dependencies.
