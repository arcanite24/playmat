Self-play swarm

Mana@Home lets people lend spare CPU to the AI's training. Workers play self-play games and upload them; the trainer replays every game before it trains on it, so a broken or dishonest worker can only waste its own time. This is early: it runs on a LAN, and the public coordinator isn't up yet.

How it works

  • A coordinator hands out work units. A unit is about a hundred games: which decks, which networks, which deals. It keeps only the metadata; the games go straight to storage (an R2 bucket, or a folder on the coordinator for a LAN).
  • Workers play units and send them back. Each game comes with its answer log, the list of every decision made in it.
  • The trainer replays every game from its answer log and accepts the unit only if every file matches its hash and the replay accepts every answer and ends the same way. Checking the recorded training data against the replay is the next step.
  • Every worker plays the same games. Workers are built strict, which pins the floating-point maths, so a Mac, a Windows PC and a Linux box (Intel or ARM) agree exactly.

Run a coordinator

The coordinator is a small container (256 MB, one core) next to your server:

cp ops/swarm/mana.env.example ops/swarm/mana.env
docker compose -f ops/swarm/docker-compose.yml up -d coordinator
docker compose -f ops/swarm/docker-compose.yml run --rm coordinator \
  token --db /data/swarm.db --role worker --name alice

token prints the token once; the coordinator keeps only its hash. Make one trainer token for yourself and one worker token per contributor. Without R2 settings, set SWARM_STORE=/data/store to keep games on the coordinator. It listens on 127.0.0.1:17190: put your reverse proxy in front of it.

Run a worker

docker run -d --name mana --restart unless-stopped --cpus 4 \
  -e MANA_COORDINATOR=https://your-coordinator -e MANA_NAME=my-pc \
  -e MANA_TOKEN=... -e MANA_JOBS=4 -v mana-work:/work ghcr.io/arcanite24/mana-worker

Or build it (cargo build --release -p playmat-worker --features strict) and run playmat-worker run --coordinator URL --name HOST --token-file F. Outside Docker it plays only while the machine is idle and hands a unit back the moment you come back to it. It always runs at the lowest priority.

Train on it

rust/rl/pfsp_league.py --run-round --swarm URL --swarm-token-file F --out DIR plans a league round, publishes it, waits, replays what comes back and puts the accepted games in DIR for train.py. rust/rl/swarm.py does the same steps one at a time.

The settings, the API and the proxy setup are in ops/swarm/README.md, and the design in docs/swarm/Design.md.
