Single sign-on

If your apps already sit behind a sign-on proxy (Authelia, Authentik, oauth2-proxy or tailscale serve), Playmat can use it: the proxy tells Playmat who signed in, and players skip Playmat's own password. This is the header-based kind; Playmat doesn't speak OIDC itself yet.

How it works

  • The proxy checks the player and adds a header with their user name, like Remote-User: alice.
  • Playmat's Caddy keeps that header only on requests from the proxy's address and deletes it from everyone else's, so a player can't send it themselves. The game server believes it only from Caddy.
  • The sign-in screen offers Continue as alice, and signs in by itself on later visits.
  • The first time, Playmat uses the account named alice (any case) or makes one. Roles, bans and the allowlist stay in the admin console.

Settings

SettingWhat it does
AUTH_TRUSTED_HEADERThe header your proxy sets. Setting it turns single sign-on on. Needs XMAGE_AUTH=true.
AUTH_TRUSTED_PROXIESWhere the proxy connects to Playmat from: IPs or ranges, separated by spaces. Empty uses UPSTREAM_PROXIES.
XMAGE_PASSWORD_SIGNINfalse makes the sign-on the only way in: no passwords, registration, reset codes or Sign in with GitHub. The admin password still opens the console.
XMAGE_TRUSTED_HEADER_STRIP_DOMAINtrue signs alice@example.com in as alice.

Which header each proxy sends:

ProxyAUTH_TRUSTED_HEADER
AutheliaRemote-User
Authentik (proxy outpost)X-authentik-username
oauth2-proxyX-Forwarded-Preferred-Username or X-Forwarded-User (with --set-xauthrequest or --pass-user-headers)
tailscale serveTailscale-User-Login, with XMAGE_TRUSTED_HEADER_STRIP_DOMAIN=true

Set it up

Put Playmat behind your proxy the way Behind another reverse proxy describes (PROXIED_HOST and UPSTREAM_PROXIES), with the proxy's sign-on check on every path, /ws included. Then add to ops/web/.env:

XMAGE_AUTH=true
AUTH_TRUSTED_HEADER=Remote-User
# keep passwords on until everyone has come through the sign-on once
XMAGE_PASSWORD_SIGNIN=true

Run up -d again. For a host Caddy in front with Authelia, the front site looks like this:

playmat.example.com {
	forward_auth authelia:9091 {
		uri /api/authz/forward-auth
		copy_headers Remote-User
	}
	reverse_proxy 127.0.0.1:8080   # Playmat's HTTP_PORT
}

Check that nobody can fake it

From a machine that reaches Playmat without going through the proxy (or through it, signed out), send the header yourself and ask the server who you are. signOn must not be in the answer:

echo '{"jsonrpc":"2.0","id":1,"method":"serverInfo","params":[]}' \
  | websocat -n1 -H 'Remote-User: owner' wss://playmat.example.com/ws

Docker can make every client look like it comes from the bridge gateway (rootless Docker, or the userland proxy). If AUTH_TRUSTED_PROXIES is that gateway, anyone who reaches Playmat's ports directly counts as the proxy. Run the check above, and keep Playmat's ports reachable only by the proxy.

Existing accounts

  • Accounts are matched by name. When your sign-on user names are the Playmat names, nothing moves: stats, decks, Career and roles stay.
  • Playmat has no rename, so where they differ, change the name in the sign-on before switching.
  • Whoever controls a name in the sign-on controls that Playmat account, the owner's included. Use a sign-on where you, not the players, choose user names.
  • Accounts made by the sign-on have no email and no password. Players can add an email in Settings, Account.
  • Turn XMAGE_PASSWORD_SIGNIN=false once everyone has signed in through the sign-on.

The Android app

The app can't pass through a sign-on proxy, so it signs in with a password. If your group uses it, keep XMAGE_PASSWORD_SIGNIN=true and a way to reach Playmat that skips the proxy.
